# 정비 사례 발행

**입력** — 구글드라이브 원본 폴더(`…\<번호. 차종 번호4자리 정비내역>\홈\`) + 젬 "웹사이트 세트" 원고.
**결과** — `index.mdx` · `images/NN.webp` · `captions.md`. 커밋까지 스킬이 한다. **푸시는 사용자가 한다.**

## 역할 경계

**사용자가 하는 일 — 스킬은 관여하지 않는다**
사진 선별 · 번호판 마스킹 · 대표 이미지 텍스트 오버레이 · 파일명 일괄 변경 · `t_`·`x_` 접두어 부착

**「홈」 폴더의 사진은 전부 쓴다고 전제한다.** 뺄 사진은 사용자가 원본 폴더에서 직접 지우거나 `x_` 접두어를 붙인다. 스킬이 "이 컷은 안 어울린다"고 판단해 빼지 않는다.

**대표 컷(`t_`) 선택은 사용자 판단 영역이다.** 도면·캡처처럼 작은 컷이어도 교체를 제안하지 않는다. 업스케일은 하지 않으므로 원본 크기·비율이 그대로 쓰인다.

**스킬이 하는 일 — 사용자에게 되묻지 않는다**
`raw/` 복사 · 리사이즈·변환 · 이미지 판독 · alt·캡션 생성 · 원고 분석 후 배치 · MDX 생성 · 빌드 · 커밋

> 사용자에게 요구해도 되는 것은 **캡션 검수 승인** 하나뿐이다. 파일명 재정렬·순서 지정·이미지 선택을 사용자에게 요청하지 않는다.

## 이 리포에서 틀리기 쉬운 지점

- 사례 URL 은 **최상위** `/<slug>/` 다. `/cases/` 하위가 아니다 (`/cases/` 는 목록·브랜드 필터 전용). 라우트: `src/pages/[...slug].astro`
- `slug` 는 프론트매터 **필수 값**이고 폴더명과 별개다. 라우팅은 프론트매터 값만 본다.
- 신규 글은 **img 모드** Figure — `<Figure img={img01} …>`. `src=` 모드는 워드프레스 이전 글 전용이다(사전 최적화된 `public/img/` 참조).
- 상세 페이지가 **제목 · 한눈에 보기 카드 · FAQ · 전환 CTA · 맺음말("바쁜 일정에도…")을 이미 렌더한다.** 본문에 같은 것을 쓰면 두 번 나온다.
- 프론트매터 필드 목록·타입의 단일 소스는 `src/content.config.ts` 다. 필드를 쓰기 전에 그 파일을 읽는다.
- 카피 규칙·불변 사실(브랜드·지역·인증·A/S)의 단일 소스는 `CLAUDE.md` 다.

## 1. 입력 확인

`slug` 를 확정한다. 명명 규칙은 **`<브랜드영문>-<차종>-<증상한글>`** 이다 (`benz-cls63-주행소음`).
허용 문자는 **영문 소문자·숫자·하이픈·한글 음절**이다. 한글은 렌더 시 퍼센트 인코딩되지만 스키마·라우팅 모두 정상 처리한다.

확인할 것:
- `src/pages/[...slug].astro` 의 `RESERVED` 목록과 충돌하지 않는다
- 기존 73건의 `slug` 와 겹치지 않는다
- 폴더명은 slug 와 같게 둔다 (다르게 둘 이유가 없다)

원고에서 차종·주행거리·증상·진단·부품·결과를 뽑아 메모한다. **원고에 없는 사실은 여기서도 뒤에서도 만들지 않는다.**

### 구버전 젬 원고 대응

사용자가 구버전 젬으로 뽑은 원고를 가져올 수 있다. 아래 구필드명이 보이면 자동 변환하고, **변환 사실을 마지막 보고에 남긴다.**

| 구필드 | 스키마 필드 | 비고 |
|---|---|---|
| `car_brand` | `brand` | |
| `pubDate` | `date` | |
| `symptom` | `symptom_customer` | 문자열이면 배열로 변환 |
| `cause` | `diagnosis_cause` | |
| `repair` | `result` | |

구버전 젬은 아래 필드를 아예 출력하지 않는다.

`seo_title` · `focus_keyword` · `symptom_tech` · `category` · `diagnostic` · `parts_used` · `summary_lead`

없으면 원고 본문에서 뽑아 채우되, **본문에 근거가 없으면 비우고 마지막 보고에서 사용자에게 알린다. 추정해서 채우지 않는다.**

## 2. 이미지 정리

```
node .claude/skills/publish-case/prepare-images.mjs <slug> --from="<원본폴더>"
```

`--from` 이 원본 폴더를 `raw/` 로 복사한 뒤 변환까지 한 번에 한다. **사용자에게 복사를 시키지 않는다.** 원본 폴더 경로를 모르면 그것만 묻는다.

### 입력 파일명 — 세 형태뿐이다

| 형태 | 예 | 처리 |
|---|---|---|
| `t_` 접두어 | `t_benz cls63 amg (1).jpg` | `thumb.webp` 로만 나간다. **본문 제외**. 정확히 1개 |
| `00_` 접두어 | `00_benz cls63 amg (14).jpg` | **선택 폴백** — 있으면 자동 식별을 무시하고 본문 첫 사진으로 고정 |
| `x_` 접두어 | `x_benz cls63 amg (17).jpg` | **발행 제외.** 변환하지 않고 번호도 주지 않는다 |
| 접두어 없음 | `benz cls63 amg (2).jpg` | 괄호 순번 오름차순 |

파일명에 공백·괄호가 들어간다. 경로는 반드시 따옴표로 감싼다.

### 정렬

키 우선순위는 **파일명 끝 괄호 순번 → 파일명 날짜 → EXIF → 파일명** 이고, **폴더 단위로 한 종류를 정해** 그 기준으로만 정렬한다. 괄호 순번이 하나라도 있으면 폴더 전체가 괄호 순번 기준이다. 파일마다 다른 척도를 섞으면 순서가 의미를 잃기 때문이다.

괄호 순번은 **정수 비교**다 — `(10)` 은 `(2)` 뒤에 온다. EXIF 는 더 이상 1순위가 아니다. 사용자가 매긴 괄호 순번이 의도된 공정 순서다.

- `t_` 가 1개가 아니면 스크립트가 **중단**한다.
- `00_` 은 **0개가 정상**이다. 0개면 3단계 자동 식별에 맡기고, 1개면 그것을 우선하며, 2개 이상이면 중단한다.
- 괄호 순번 결번·중복은 **경고만** 하고 계속 진행한다. 접두어 파일의 번호까지 합산해 1~N 연속인지 본다.
- 출력 말미의 `MANIFEST`(번호·원본파일·`paren`·`taken`·크기)를 5단계까지 들고 간다.

**번호는 잠정값이다.** 4단계에서 배치가 확정된 뒤 재부여한다.

## 3. 판독

정렬된 이미지를 **한 장도 빠짐없이** Read 로 실제로 열어보고 아래를 판정한다. 보지 않고 파일명·순서로 추측하지 않는다.

| 항목 | 내용 |
|---|---|
| 피사체 | 차량 전체 / 엔진룸 / 하부 / 부품 단품 / 계기판 / 도면 / 소모품 등 |
| 부위 | 등속조인트, 스테빌라이저, 오일필터, 에어클리너 등 식별 가능한 범위까지 |
| 상태 | 탈거 전 / 탈거 후 / 신품 / 구품 / 파손 부위 노출 여부 |
| 공정 단계 | 입고 · 점검 · 원인 확인 · 부품 준비 · 작업 · 완료 · 출고 |

### 본문 첫 사진 자동 식별

**본문 첫 사진은 사용자가 지정하지 않는다. 스킬이 텍스트 오버레이 컷을 스스로 찾는다.**
`00_` 파일이 있으면 자동 식별을 건너뛰고 그것을 쓴다.

판독 중 **텍스트 오버레이가 얹힌 컷**(제목·문구가 이미지 위에 합성된 컷)을 후보로 모은다.

| 후보 수 | 처리 |
|---|---|
| 1개 | 그것으로 확정 |
| 0개 | 괄호 순번이 가장 빠른 사진을 쓰고, 검수 출력에 `⚠ 오버레이 컷 미검출` 표시 |
| 2개 이상 | 확신도가 가장 높은 하나를 쓰고, **후보 전체를 검수 출력에 나열** |

**어느 경우에도 중단하지 않는다.** 확정한 컷은 4단계 `--renumber` 로 `01.webp` 자리에 세운다.

### 판독 원칙

- **원고에 근거가 없는 부위명을 지어내지 않는다.** 원고에 등속조인트와 스테빌라이저만 나오면, 하부 사진을 제3의 부품으로 판정하지 않는다.
- 두 부품이 시각적으로 구분되지 않으면 **불확실 표시**를 남긴다. 추측으로 확정하지 않는다.
- 도면·부품 카탈로그 이미지는 실물 사진과 구분해 판정한다.

### 중단 조건

- **마스킹 누락** — 번호판이 그대로 읽히는 컷이 있으면 발행을 중단하고 해당 컷 번호를 알린다. 사전 처리 누락일 가능성이 있으므로 그냥 넘기지 않는다.
- **원인 근접샷 없음** — 고장 부위를 가까이 찍은 컷이 한 장도 없으면 발행을 중단하고 알린다.

## 4. 배치

젬 원고를 문단 단위로 분해하고, 각 문단이 다루는 공정 단계에 이미지를 배치한다.

- 원고 문단 순서가 곧 공정 순서다. 이미지 정렬 순서와 원고 순서가 어긋나면 **원고를 기준**으로 삼되, 어긋난 사실을 보고한다.
- 한 문단에 몰리지 않게 분산한다. **문단당 1~3장** 기준.
- `00_` 컷은 항상 본문 최상단, 첫 문단 앞.
- 대응 문단이 없는 이미지는 가장 가까운 공정 단계에 붙이고 보고에 명시한다.

### 번호 재부여

배치가 확정되면 **본문 순서와 파일 번호를 일치시킨다.**

```
node .claude/skills/publish-case/prepare-images.mjs <slug> --renumber=1,3,2,…
```

`--renumber=1,3,2` 는 "새 01 = 기존 01, 새 02 = 기존 03, 새 03 = 기존 02". 1~N 을 중복 없이 한 번씩 쓴다. 순서가 이미 맞으면 실행하지 않아도 된다.

## 5. alt 텍스트 · 캡션

### alt

형식: **`지역 + 브랜드 차종 + 부위 + 상태`**

```
동탄 벤츠 CLS63 AMG 전륜 등속조인트 부츠 파손 상태
동탄 벤츠 CLS63 AMG 스테빌라이저 부싱 유격 점검
동탄 벤츠 CLS63 AMG 신품 등속조인트 좌우 2개
동탄 벤츠 CLS63 AMG 등속조인트 부품 도면
```

- **모든 정비 사진에 alt 를 부여한다.** 장식용 이미지는 없다고 간주한다.
- 브랜드 표기는 `src/data/caseBrands.ts` 정본을 따른다.
- 도면은 `상태` 자리를 "부품 도면"으로 채운다 — 형식은 하나로 유지한다.

### 캡션

- **담담한 해요체 존댓말 한 문장, 60자 이내.** CLAUDE.md 의 톤 규칙이 우선한다.
- 사진에 실제로 보이는 것만 쓴다. 사진에 없는 수치·판단을 넣지 않는다.
- **주행거리는 젬 원고 값이 정본이다.** 계기판 사진의 숫자가 원고와 달라도 원고를 고치지 않고, **캡션에서 수치를 뺀다**(`"계기판에서 누적 주행거리를 확인했어요."`). 불일치는 보고하지 않는다 — 이 규칙으로 처리하고 넘어간다.
- 장비·부품은 실명으로.
- **금지어** — 말끔히 / 완벽히 / 완연히 / 확실히 / 새 차처럼 / 걱정 없이 / 최상의 / 최고의 / 제일 / 정확한 / 완전히 사라지고 / 되찾아진
- 차량번호·VIN 을 쓰지 않는다.

## 6. 캡션 검수표

**중간에 묻지 않는다. 끝까지 진행한다.** 판단이 필요한 지점은 스킬이 정하고 검수표에 표시만 남긴다. 사용자는 완성된 결과를 보고 확인한다.

**멈추는 경우는 발행을 물리적으로 못 할 때뿐이다** — 파일 누락, 빌드 실패, 3단계 중단 조건(마스킹 누락·원인 근접샷 없음).

**예외 — 기존 사례에 영향을 주는 수정은 적용 전에 알린다.** 이번 건을 위한 수정이 다른 사례의 렌더 결과를 바꾸면 멈추고 보고한다. 공용 코드(`src/layouts/`·`src/pages/[...slug].astro`·`src/components/Figure.astro`·`src/data/`)를 건드릴 때가 여기 해당한다. 영향 범위를 실측해 몇 건이 어떻게 바뀌는지 함께 낸다.

검수표는 마지막 보고와 `captions.md` 에 함께 낸다.

```
[캡션 검수]

01.webp  ← 00_benz cls63 amg (14).jpg
  배치: 도입부
  alt : 동탄 벤츠 CLS63 AMG 하체 소음 정비 입고
  캡션: 주행 중 하체 소음으로 입고된 차량입니다.

02.webp  ← benz cls63 amg (21).jpg
  배치: 1문단 (입고)
  alt : 동탄 벤츠 CLS63 AMG 계기판 주행거리 확인
  캡션: 누적 주행거리 112,000km 를 확인했어요.

06.webp  ← benz cls63 amg (15).jpg   ⚠ 판독 불확실
  배치: 2문단 (하부 점검)
  alt : 동탄 벤츠 CLS63 AMG 하부 서스펜션 점검
  캡션: 하부 점검에서 부싱 유격이 확인됐어요.
  사유: 등속조인트/스테빌라이저 구분이 시각적으로 불확실
```

- 판독이 불확실한 항목은 `⚠` 로 표시하고 **사유**를 적는다. 표시만 하고 진행은 멈추지 않는다.
- 사용자가 나중에 특정 항목만 수정 지시하면 **그 항목만** 반영하고 나머지는 유지한다.

## 7. index.mdx 작성

`src/content/cases/<slug>/index.mdx` 를 만든다. 구조는 기존 사례(`src/content/cases/audi-a4-20tdi-timing-belt-water-pump-dongtan/index.mdx`)와 같되, Figure 는 img 모드로 쓴다.

```mdx
---
(프론트매터 — 필드는 src/content.config.ts 참조)
---
import Figure from '../../../components/Figure.astro';
import img01 from './images/01.webp';
import img02 from './images/02.webp';

안녕하세요? 동탄 수입차 전문정비 모터 리페어입니다.

<Figure img={img01} alt="…" caption="…" />

(본문 — 4단계에서 확정한 배치대로)
```

- 사용하는 이미지만 import 한다. 쓰지 않을 컷은 import 하지 않는다.
- `thumb.webp` 는 본문에 넣지 않는다 — 목록·og:image 전용이다.
- `figcaption` 은 쓰지 않는다 — 스키마 기본값이 `true` 다.
- 본문 마지막 줄: `매장 위치와 문의 방법은 [오시는 길](/location/)에서 확인하실 수 있습니다.`

**프론트매터 전체 — 출처와 규칙:**

| 필드 | 출처 | 규칙 |
|---|---|---|
| `title` | 젬 | 그대로 |
| `seo_title` | 젬 | 그대로. title과 같아도 무방 |
| `slug` | 스킬 확정 | 젬이 준 "슬러그 후보"를 검증해 확정. 영문 소문자·하이픈 |
| `date` | 젬 | YYYY-MM-DD. 젬이 오늘 날짜를 넣었으면 사진 촬영일과 대조해 작업일로 고친다 |
| `focus_keyword` | 젬 | 그대로 |
| `description` | 젬 | 160자 이하. 초과 시 스키마가 막는다 |
| `brand` | 젬 | 한글. `src/data/caseBrands.ts` 그룹 값과 일치해야 필터에 잡힌다 |
| `car_model` | 젬 | `브랜드 모델 (연식)`. 연식 없으면 모델명만 |
| `mileage_km` | 젬 | 숫자만. 젬이 생략했으면 필드째 생략. 지어내지 않는다. **계기판 사진과 달라도 원고를 고치지 않는다** |
| `symptom_customer` | 젬 | 배열. 고객 언어 2~3개 |
| `symptom_tech` | 젬 | 문자열 1줄 |
| `category` | 젬 | `메인터넌스(소모품 교환)` 또는 `고장 진단(○○ 계통)` |
| `diagnostic` | 젬 | 배열. 원고에 실제 등장한 진단 행위만 |
| `parts_used` | 젬 | 배열. 부품명 + 등급 (순정)(OEM)(애프터마켓) |
| `result` | 젬 | 문자열 1줄 |
| `region` | — | 쓰지 않는다. 스키마 기본값 사용 |
| `tags` | 젬 | 배열 8~10개. 지역 태그는 동탄·화성·오산·평택만, 2개 이내 |
| `thumbnail` | 스킬 | `./images/thumb.webp` 리터럴 고정 |
| `figcaption` | 스킬 | 신규 글은 명시하지 않는다 (스키마 기본값 true) |
| `summary_lead` | 젬 | 자기완결 한 문장 |
| `diagnosis_cause` | 젬 | 문자열 1줄 |
| `faq` | 젬 | 정확히 3개. 2개·4개는 빌드 실패 |

전용 진단기(ISTA+·Xentry·ODIS·VCDS·PIWIS)는 주력 6개 브랜드에만 해당한다. 재규어·랜드로버·마세라티 등 확장 브랜드 글에 전용 진단기를 쓰지 않는다.

## 9. 사전 점검 · 빌드

### 빌드 전에 자체 확인한다

- `description` 160자 이하
- `faq` 정확히 3개
- `brand` 가 `caseBrands.ts` 그룹 값과 일치
- 필수 필드가 모두 있다 (`mileage_km`·`region`·`figcaption` 제외)
- `thumbnail` 이 `./images/thumb.webp` 이고 실제 파일이 존재
- `slug` 가 기존 73건과 중복되지 않고 `RESERVED` 와 충돌하지 않는다
- 본문에 `<br>`·소제목·FAQ·맺음말("바쁜 일정에도…")이 없다
- 차량번호·VIN 이 alt·캡션·본문·slug 어디에도 없다
- import 한 이미지가 전부 `<Figure>` 로 쓰였고, 쓰지 않은 import 가 없다
- 본문 마지막 줄에 오시는 길 안내가 있다
- `t_` 파일이 정확히 1개였다
- `00_` 은 0개(자동 식별) 또는 1개(수동 지정)였다 — 2개 이상만 중단 사유다
- 본문 첫 사진이 확정됐다 (자동 식별 결과 또는 `00_`). 미검출·복수 후보는 검수 출력에 표시했다
- 괄호 순번 결번·중복 경고를 확인했다 (경고일 뿐 중단 사유는 아니다)
- 모든 본문 이미지에 alt 와 캡션이 있다
- 캡션 금지어 검사 — **걸리면 경고만 하고 중단하지 않는다.** "정확한" 같은 단어는 오탐이 잦다. 기계적으로 막으면 사람이 경고 자체를 무시하게 되고, 그러면 진짜 금지어도 함께 흘러간다. 걸린 문장을 보고하고 판단은 사용자에게 맡긴다.
- 판독 불확실(`⚠`) 항목이 6단계 검수를 거쳤다

### 빌드

```
npm run build
```

통과 기준 — 아래가 **전부** 확인돼야 이 단계가 끝난다:
- 빌드 성공 (스키마 오류·깨진 import 없음)
- 페이지 수가 직전보다 1 늘었다
- `dist/<slug>/index.html` 이 생겼다
- 그 HTML 에 `<Figure>` 로 넣은 이미지가 전부 들어 있다

실패하면 원인을 고치고 다시 돌린다.

## 10. 커밋 · 보고

빌드가 통과하면 **커밋까지 한다. 푸시는 하지 않는다** — main 푸시는 Cloudflare 자동 배포로 곧장 라이브 반영이라 사용자가 직접 올린다.

`images/` 는 저장소에 커밋된다(`.gitignore` 는 `raw/` 만 제외한다). 구글드라이브 원본이 지워져도 사이트 이미지는 영향받지 않는다.

보고할 것:
- 생성 경로 (`index.mdx`, 이미지 N장, `captions.md`)
- 빌드 결과 (페이지 수 변화)
- **구버전 젬 원고였다면 변환한 필드 목록**
- **원고에 근거가 없어 비워 둔 필드** — 사용자가 직접 채워야 하는 것
- **정렬 순서와 원고 순서가 어긋나 원고를 따른 이미지**
- **대응 문단이 없어 인접 단계에 붙인 이미지**
- 괄호 순번 결번·중복 경고, 금지어 경고
- 다음 행동: 커밋 확인 → `git push`

발행이 끝나면 `raw/` 는 지워도 된다(gitignore 대상이라 커밋되지 않는다). 지울지는 사용자에게 묻는다.
