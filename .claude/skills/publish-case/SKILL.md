# 정비 사례 발행

**입력** — `src/content/cases/<slug>/raw/` 에 떨군 원본 사진(순서·HEIC·용량 무관) + 젬 "웹사이트 세트" 원고.
**결과** — `index.mdx` · `images/NN.webp` · `captions.md`(사용자 리뷰용). 커밋·푸시는 사용자가 한다.

## 이 리포에서 틀리기 쉬운 지점

- 사례 URL 은 **최상위** `/<slug>/` 다. `/cases/` 하위가 아니다 (`/cases/` 는 목록·브랜드 필터 전용). 라우트: `src/pages/[...slug].astro`
- `slug` 는 프론트매터 **필수 값**이고 폴더명과 별개다. 라우팅은 프론트매터 값만 본다.
- 신규 글은 **img 모드** Figure — `<Figure img={img01} …>`. `src=` 모드는 워드프레스 이전 글 전용이다(사전 최적화된 `public/img/` 참조).
- 상세 페이지가 **제목 · 한눈에 보기 카드 · FAQ · 전환 CTA · 맺음말("바쁜 일정에도…")을 이미 렌더한다.** 본문에 같은 것을 쓰면 두 번 나온다.
- 프론트매터 필드 목록·타입의 단일 소스는 `src/content.config.ts` 다. 필드를 쓰기 전에 그 파일을 읽는다.
- 카피 규칙·불변 사실(브랜드·지역·인증·A/S)의 단일 소스는 `CLAUDE.md` 다.

## 1. 입력 확인

`slug` 를 확정한다 — 영문 소문자·하이픈, 브랜드+차종+작업이 드러나게 (`bmw-520d-coolant-leak`).

확인할 것:
- `src/pages/[...slug].astro` 의 `RESERVED` 목록과 충돌하지 않는다
- 기존 73건의 `slug` 와 겹치지 않는다
- 폴더명은 slug 와 같게 둔다 (다르게 둘 이유가 없다)

원고에서 차종·주행거리·증상·진단·부품·결과를 뽑아 메모한다. **원고에 없는 사실은 여기서도 뒤에서도 만들지 않는다.**

## 2. 이미지 정리

```
node .claude/skills/publish-case/prepare-images.mjs <slug> --thumb=N
```

EXIF 촬영시각 오름차순(= 공정 순서)으로 `images/01.webp …` 를 만들고, `--thumb=N` 번째 컷을 `thumb.webp` 로 만든다. 가로 2000px 상한 · EXIF 제거 · WebP q80. 반응형 변환은 astro:assets 가 빌드 때 한다.

- `--thumb` 은 대표 컷 번호다. 어느 컷이 대표인지 3단계에서 사진을 본 뒤 정해도 되고, 그때 스크립트를 다시 돌려도 된다.
- "EXIF 촬영시각 없음" 경고가 뜨면 그 사진들은 파일명 순으로 뒤에 붙는다. 3단계에서 내용을 보고 순서를 바로잡는다.
- 출력 말미의 `MANIFEST` (번호·파일명·촬영시각·크기)를 4단계까지 들고 간다.

## 3. 사진 판독 — alt·캡션

`images/` 의 이미지를 **한 장도 빠짐없이** Read 로 실제로 열어보고, 본문 맥락과 합쳐 각 장의 alt 와 caption 을 쓴다. 보지 않고 파일명·순서로 추측해 쓰지 않는다.

**alt** — `지역 + 브랜드/차종 + 무엇을 하는 장면`. 지역은 동탄 기준.
`"동탄 수입차 정비소 BMW 520d 하부 오일팬 드레인 폐유 배출"`
장식용 컷(간판·외관 등 정보가 없는 컷)은 빈 문자열.

**caption** — 담담한 해요체 한 문장. 장비·부품은 실명으로.
`"드레인 볼트를 풀어 폐유를 완전히 빼내게 됩니다."`

사진에 보이는 것만 쓴다. 진단기 화면이면 화면에 뜬 것을, 부품이면 그 부품의 상태를 쓴다.

## 4. index.mdx 작성

`src/content/cases/<slug>/index.mdx` 를 만든다. 구조는 기존 사례(`src/content/cases/audi-a4-20tdi-timing-belt-water-pump-dongtan/index.mdx`)와 같되, Figure 는 img 모드로 쓴다.

```mdx
---
(프론트매터 — 필드는 src/content.config.ts 참조)
---
import Figure from '../../../components/Figure.astro';
import img01 from './images/01.webp';
import img02 from './images/02.webp';

안녕하세요? 동탄 수입차 전문정비 모터 리페어입니다.

<Figure img={img01} alt="…" caption="…" />

(본문 — 공정 순서대로)
```

- 사용하는 이미지만 import 한다. 쓰지 않을 컷은 import 하지 않는다.
- `<Figure>` 는 본문 단락 경계에 공정 순서로 넣되, 사진 내용에 맞춰 위치를 맞춘다 — 진단기 화면은 진단 단락, 파츠 박스는 부품 입고 단락, 외관은 도입/결론.
- `figcaption: true` (신규 글 기본값 — 캡션을 쓰므로).
- 본문 마지막 줄: `매장 위치와 문의 방법은 [오시는 길](/location/)에서 확인하실 수 있습니다.`

**프론트매터에서 판단이 필요한 필드:**

| 필드 | 규칙 |
|---|---|
| `slug` | 1단계에서 확정한 값. 따옴표로 감싼다 |
| `brand` | 한글 표기. `src/data/caseBrands.ts` 의 그룹 값과 맞아야 필터에 잡힌다 (BMW·미니·벤츠·아우디·폭스바겐·포르쉐·재규어·랜드로버, 그 밖은 "기타" 그룹) |
| `car_model` | `브랜드 모델 (연식)`. 연식이 원고에 없으면 모델명만 |
| `mileage_km` | 원고에 수치가 있을 때만 숫자로. 없으면 **필드를 생략**한다 |
| `category` | `메인터넌스(소모품 교환)` 또는 `고장 진단(○○ 계통)` |
| `diagnostic` | 원고에 실제로 등장한 장비·진단 행위만. 원고가 "시스템 진단기"라고만 하면 그대로 쓴다 |
| `symptom_customer` | 고객 언어 2~3개 ("경고등이 떴어요" 체). 상세 페이지 CTA 예시 문구로도 쓰인다 |
| `description` | 160자 이하 (스키마가 막는다) |
| `summary_lead` | `모터리페어는 경기 화성 동탄의 수입차 전문 정비소로, <차종>(주행 Nkm)의 <증상>을 <진단>해 <정비>했습니다.` 자기완결 한 문장 |
| `faq` | **정확히 3개.** 답은 원고의 사실 범위 안에서 |
| `tags` | 차종·작업·지역 키워드. 지역 태그는 동탄·화성·오산·평택만 |
| `region` | 쓰지 않는다 — 스키마 기본값을 쓴다 |

전용 진단기(ISTA+·Xentry·ODIS·VCDS·PIWIS)는 주력 6개 브랜드에만 해당한다. 재규어·랜드로버·마세라티 등 확장 브랜드 글에 전용 진단기를 쓰지 않는다.

## 5. captions.md

`src/content/cases/<slug>/captions.md` 에 리뷰용 표를 쓴다 — 사용자가 캡션만 훑고 고칠 수 있게.

## 6. 빌드 검증

```
npm run build
```

통과 기준 — 아래가 **전부** 확인돼야 이 단계가 끝난다:
- 빌드 성공 (스키마 오류·깨진 import 없음)
- 페이지 수가 직전보다 1 늘었다
- `dist/<slug>/index.html` 이 생겼다
- 그 HTML 에 `<Figure>` 로 넣은 이미지가 전부 들어 있다

실패하면 원인을 고치고 다시 돌린다.

## 7. 보고

사용자에게 이것만 전한다:
- 생성 경로 (`index.mdx`, 이미지 N장, `captions.md`)
- 빌드 결과 (페이지 수 변화)
- 판단이 갈렸던 지점 — 원고에 없어 비운 필드, 순서를 바꾼 사진, 쓰지 않고 남긴 컷
- 다음 행동: `captions.md` 검토 → 커밋 → 푸시

**커밋·푸시는 하지 않는다.** 사용자가 캡션을 검토한 뒤 지시한다.

발행이 끝나면 `raw/` 는 지워도 된다(gitignore 대상이라 커밋되지 않는다). 지울지는 사용자에게 묻는다.
