## 0. 이 문서의 위치

원고 생성 시 이 문서와 `문체예시/` 폴더를 함께 읽는다.
문체는 예시에서, 규칙은 이 문서에서 가져온다. **둘이 충돌하면 이 문서가 우선한다.**

---

## 1. 기본 전제 (절대 규칙)

이 지침은 해석 대상이 아닌 기준이며, 위반 시 결과물은 무효로 본다.
임의 판단·추정·생략을 금지한다. 근거가 없으면 비우고 보고한다.

차대번호(VIN)가 주어지면 조회해 제원을 확인하고 원고에 반영한다. **단 VIN 자체는 글에 넣지 않는다.**

## 2. 문체 및 브랜드 보이스

**톤:** 존댓말 기반. 친근하되 기술적으로 중립적인 전문가의 어투.

**담담한 어투 (감정 배제):** 과장된 미사여구나 감정적 표현을 지양하고 담백하게 서술한다. 자랑·확신에 찬 어투를 쓰지 않는다.

**구조:** 소제목을 쓰지 않고 문단 구분으로만 전개한다.

**가독성:** 마침표 다음은 줄바꿈해서 새 문장을 시작한다. 단락 구분 필수.

### 시그니처 표현 (필수 포함)

```
"오늘도 담담하게 정비의 진도를 나가게 됩니다."
"워크베이에 차량을 안착시킨 후 루틴이죠."
"~하게 되죠."
```

### 감상·추임새 금지 (절대 규칙, 2026-09-15 신설)

본문은 **차량 상태와 작업 사실만** 서술한다. 아래 유형의 문장을 쓰지 않는다.

| 금지 유형 | 예시 |
|---|---|
| 정비사·고객의 감정이나 소감 | "쉽지 않은 작업이었습니다", "다행입니다" |
| 독자에게 말을 거는 추임새 | "지켜볼 내용이 제법 많군요", "만만치 않습니다" |
| 서술을 꾸미는 감탄조 어미 | "~군요", "~인 듯싶군요", "제법 많습니다" |

```
✗ 하부에서 플렉시블 디스크의 크랙이 눈에 들어오는군요.
  지켜볼 내용이 제법 많군요.

✓ 하부에서 플렉시블 디스크의 크랙이 진행된 상태가 확인됩니다.
```

점검 항목이 많아도 그 사실을 말로 덧붙이지 않는다. 항목을 나열하는 것으로 충분하다.

> 이전 지침의 **"간헐적 삽입 표현 — 지켜볼 내용이 제법 많군요"** 항목은 폐기했다. 시그니처 표현 목록에서 `"~인 듯싶군요."` 도 함께 삭제했다.

### 볼드·마크업 강조 금지 (절대 규칙, 2026-09-15 신설)

**별표(`*`)를 어디에도 쓰지 않는다.** 본문·제목·소제목·표기 전부 해당하며 네이버 세트와 Astro 세트 모두 적용된다.

```
✗ **예열 플러그**는 냉간 시동 시 연소실 온도를 끌어올리는 부품입니다.
✓ 예열 플러그는 냉간 시동 시 연소실 온도를 끌어올리는 부품입니다.
```

강조가 필요하면 **문장 구성으로** 처리한다 — 해당 부품을 문장의 주어로 세우거나, 한 문장을 그 부품에만 할애한다.

> 이전에 쓰이던 "볼드체로 핵심 키워드·부품명 강조" 지시는 폐기했다.

### 금지어 (절대 규칙)

결과를 보장하는 표현이라 분쟁 소지가 있다. 네이버 세트와 Astro 세트 모두 해당된다.

```
말끔히 · 완벽히 · 완연히 · 확실히 · 새 차처럼 · 걱정 없이
최상의 · 최고의 · 제일 · 정확한 · 완전히 사라지고 · 되찾아진
```

추가 금지: `대략` · `약` · `충분히` · `나이스합니다` 등 모호하거나 과한 표현.

작성 완료 후 본문에 위 단어가 있는지 반드시 검사한다.

> ⚠️ **문체 예시 파일에 금지어가 포함된 곳이 있다.** 예시는 어투와 문장 리듬을 참고하는 용도이며, 금지어 사용까지 따라가서는 안 된다. 해당 위치는 `문체예시/README.md` 참조.

## 3. 분량 및 FAQ

**네이버 세트 본문:** 공백 제외 1,000~1,500자 엄수. 작성 후 FAQ 하단에 글자수를 기재한다. (2026-09-15 개정 — 이전 기준은 1,500~2,000자였다.)

**Astro 세트:** 글자수를 기재하지 않는다.

**FAQ:** 본문 하단에 정확히 3개. 2개 또는 4개는 규칙 위반이다. 헤더는 "FAQ"로만 표기하며 "(소비자 관점 질문 및 답변)" 같은 부제를 붙이지 않는다. FAQ 분량은 본문 글자수에 포함하지 않는다.

---

## 4. 출력 구성

출력 순서는 **① 네이버 → ② Astro** 로 고정한다. 두 세트를 모두 출력하기 전에 중간에서 멈추지 않는다.

워드프레스 세트는 운영 종료로 폐기되었다. HTML 본문도 출력하지 않는다.


## 6. Astro 세트

### 출력 방식

프론트매터와 본문을 하나의 코드블록에 담는다. 코드블록 앞에 슬러그 후보를 한 줄로 별도 출력한다.

```
슬러그 후보: benz-cls63-주행소음
```

프론트매터 안에 `slug` 줄을 넣지 않는다. 최종 확정은 발행 도구가 한다.

### 프론트매터 필드

필드명이 하나라도 다르면 빌드가 실패한다. 임의로 바꾸지 않는다.

```yaml
---
title: "일반 제목"
seo_title: "SEO 제목"
date: 2026-08-30
focus_keyword: "초점 키프레이즈"
description: "메타 디스크립션 — 160자 이하 절대 엄수"
brand: "벤츠"
car_model: "벤츠 CLS63 AMG 4Matic (2015년식)"
mileage_km: 112000
symptom_customer: ["주행할 때 하체에서 소리가 나요"]
symptom_tech: "주행 112,000km — 전륜 등속조인트 부츠 파손 및 베어링 마모"
category: "고장 진단(하체 구동 계통)"
diagnostic: ["스캐너 시스템 고장 코드·서비스 데이터 스캔", "테스트 주행 소음 확인"]
parts_used: ["전륜 좌우 등속조인트", "스테빌라이저 센터", "엔진오일 PETRONAS 0W40"]
result: "등속조인트·스테빌라이저 교환 후 하체 소음 개선, 후륜 에어챔버 파츠 대기"
tags: ["벤츠", "CLS63AMG", "동탄벤츠정비", "화성수입차정비"]
summary_lead: "모터리페어는 경기 화성 동탄의 수입차 전문 정비소로, …"
diagnosis_cause: "전륜 좌우 등속조인트 부츠 파손에 따른 구리스 유출과 내부 베어링 마모"
faq:
  - q: "질문1"
    a: "답변1"
  - q: "질문2"
    a: "답변2"
  - q: "질문3"
    a: "답변3"
---
```

### 필드별 규칙

| 필드 | 규칙 |
|---|---|
| `title` | 일반 제목 그대로 |
| `seo_title` | SEO 제목 그대로. title과 같아도 무방 |
| `date` | **작성일(발행일) 기준. 예외 없음.** 촬영일과 달라도 고치지 않는다 |
| `focus_keyword` | 초점 키프레이즈 그대로 |
| `description` | **160자 이하.** 작성 후 반드시 글자수를 센다 |
| `brand` | 허용값만: BMW / 미니 / 벤츠 / 아우디 / 폭스바겐 / 포르쉐 / 재규어 / 랜드로버 / 기타 |
| `car_model` | "브랜드 모델 (연식년식)". 연식이 없으면 모델명만 |
| `mileage_km` | 숫자만. **원고.txt 값을 그대로 쓴다.** 계기판 사진과 달라도 고치지 않는다. 값이 없으면 줄 전체를 생략한다. 추정 금지 |
| `symptom_customer` | 배열. 고객이 실제 쓰는 말 2~3개. O: "시동 걸 때 덜덜거려요" / X: "엔진 부조 현상 발생" |
| `symptom_tech` | 문자열 1줄. 정비사 언어. 주행거리 + 확인된 기술적 상태 |
| `category` | "메인터넌스(소모품 교환)" 또는 "고장 진단(○○ 계통)" |
| `diagnostic` | 배열. **원고에 실제로 등장한 진단 행위만.** 진단기 실명 금지 — §7 참조 |
| `parts_used` | 배열. **출처 구분 괄호를 붙이지 않는다** (아래 별도 항목 참조) |
| `result` | 문자열 1줄. 정비 후 상태와 출고 상황 |
| `tags` | 배열 8~10개. 차종·작업·지역 축. 지역 태그는 동탄·화성·오산·평택만, 2개 이내 |
| `summary_lead` | 자기완결 한 문장. 이 문장만 떼어 읽어도 무슨 사례인지 알 수 있어야 한다 |
| `diagnosis_cause` | 문자열 1줄. 진단으로 확인된 원인만 |
| `faq` | 정확히 3개. 2개·4개는 빌드 실패 |

### `summary_lead` 템플릿

```
모터리페어는 경기 화성 동탄의 수입차 전문 정비소로,
<차종>(주행 N km)의 <증상>을 <원인>으로 진단해 <정비>했습니다.
```

### 출력하지 않는 필드

아래 4개는 발행 도구가 채운다. 프론트매터에 넣지 않는다.

```
slug        기존 글 중복 검사가 필요하다
thumbnail   이미지 처리 도구가 만든다
figcaption  시스템 기본값
region      시스템 기본값
```

### 부품 출처 표기 (2026-08-30 개정)

`parts_used` 등 요약 필드에 **본문 근거 없는 출처 구분을 붙이지 않는다.**

```
엔진오일 FUCHS TITAN 5W30(애프터마켓)  →  엔진오일 FUCHS TITAN 5W30
오일필터(OEM)                          →  오일필터
```

**예외:** 본문에서 부품 선택 자체를 다룬 경우에는 남긴다. 예를 들어 "스테빌라이저는 센터 순정 부품으로, 전륜 등속조인트는 애프터 파츠로 발주했다"는 서술이 본문에 있으면 `parts_used`에도 표기를 유지한다.

판정 기준: **본문에 해당 출처 언급이 있으면 남기고, 없으면 뗀다.** 애매하면 제거하고 검수 출력에 표시한다.

### 마크다운 본문 — 금지 사항

```
✗ <br>, <p>, <section> 등 모든 HTML 태그
✗ style 속성, 인라인 CSS
✗ 소제목 (##, ###)
✗ 이미지 태그, Figure 태그      ← 사진 배치는 발행 도구가 한다
✗ 결론부 고정 문구              ← 사이트 템플릿이 자동 렌더링하므로 중복
✗ FAQ 본문 재기재               ← 프론트매터 faq 필드가 유일한 위치
✗ 본문 글자수 표기
✗ "오시는 길" 안내 문장          ← 발행 도구가 마지막 줄에 붙인다
```

줄바꿈은 태그가 아니라 실제로 줄을 나누어 표현한다.

**본문 종료 지점:** 차량 인도 문장에서 끝낸다. 그 이후 어떤 문장도 추가하지 않는다.

### 문단 구분 (절대 규칙)

본문은 반드시 4개 문단으로 나누고, 문단 사이에 빈 줄을 1개 넣는다.

| 문단 | 내용 | 분량 |
|---|---|---|
| 1문단 | 인사·차량정보·입고 경위 ("어제와 같이.."로 끝냄) | 4~5줄 |
| 2문단 | 워크베이 안착·시스템 진단·실차 점검 결과 | 5~7줄 |
| 3문단 | 파츠 오더·탈착·신품 교환·조립 | 6~8줄 |
| 4문단 | 시운전·출고 | 3~4줄 |

**3문단이 가장 길어야 한다.** 정비 과정이 글의 핵심이다. 탈착·교환·조립 각 공정을 뭉뚱그리지 말고 순서대로 서술한다. 원고.txt에 적힌 작업 항목이 본문에 최소 한 문장씩 반영되어야 한다.

### 사진 캡션 — 출력하지 않는다

캡션과 alt는 사진을 실제로 판독하는 발행 단계에서 작성한다. 원고 생성 단계에서는 쓰지 않는다.

## 7. 기술 서술 규칙

**정비 흐름:** 파츠 오더 → 입고 → 탈착 → 조립(분해의 역순)

**표현:** "추정" 대신 "판단됩니다". 기술적 수치와 공정은 객관적으로 서술한다.

### 진단 장비 표기 (절대 규칙)

**진단 장비 실명을 어디에도 쓰지 않는다** (2026-09-15 개정). ISTA · ISTA+ · Xentry · ODIS · VCDS · PIWIS · Picoscope 전부 해당한다.

| 위치 | 표기 |
|---|---|
| 네이버 본문 | "스캐너 시스템" 또는 "전용 진단 장비" |
| Astro 본문 | "시스템 진단기" 또는 "제조사 전용 진단기" |
| Astro `diagnostic` 필드 | "스캐너 시스템 ○○ 점검" 형태. 실명 금지 |
| alt · 캡션 · 태그 · title · seo_title · description · focus_keyword | 실명 금지 |

> 이전 지침의 **"Astro `diagnostic` 필드만 실명 허용"** 예외는 폐기했다. 전 채널·전 필드에서 실명을 쓰지 않는다.

### 브랜드 표기 규칙 (절대 규칙)

전용 진단기를 보유한 브랜드는 **BMW·미니·벤츠·아우디·폭스바겐·포르쉐 6종**이다.

그 외 브랜드(재규어·랜드로버·마세라티·렉서스·닛산·포드·볼보·캐딜락·피아트 등) 정비 글에서는 "브랜드 전용 진단기", "전용 진단 시스템" 표현을 쓰지 않는다. 본문뿐 아니라 메타 디스크립션·태그에도 넣지 않는다. 사실과 다른 서술이 된다.

`brand` 필드 정본 표기는 `BMW·MINI` — 가운뎃점 앞뒤 공백 없음, MINI는 영문.

### 지역 표기

서비스 지역은 **동탄·화성·오산·평택**으로 통일한다. 그 외 지역명을 주력 지역처럼 서술하지 않는다.

## 8. 차량 개인정보 (절대 규칙)

**차량번호를 텍스트 어디에도 쓰지 않는다.** 제목·본문·슬러그·태그·description·FAQ·alt·캡션 전부 해당된다. 원고.txt에 차량번호 뒷자리가 포함돼 있어도 출력물에서 제거한다.

차대번호(VIN)도 전체를 노출하지 않는다. 제원 조회에만 쓴다.

이 규칙은 네이버 세트에도 동일하게 적용한다.

> 사진에 찍힌 차량번호는 별개다. 마스킹 여부는 사용자가 원본 단계에서 판단하며, 발행 도구는 받은 사진을 그대로 쓴다. **사진에 우연히 담긴 것과 텍스트로 적어 검색에 걸리게 만드는 것은 성격이 다르다.**

## 9. 슬러그 명명 규칙

```
<브랜드영문>-<차종>-<증상한글>     예: benz-cls63-주행소음
```

- 브랜드 토큰: `bmw` `benz` `audi` `vw` `mini` `porsche` (그 외는 영문 표기)
- 차종: 제조사 표기 소문자, 공백 제거. 서브 등급(AMG·M 등) 생략
- 증상: 고객 언어의 명사형, 띄어쓰기 없이 붙여씀
- 중복 시 뒤에 `-2` `-3`
- 차량번호·VIN·관리번호·날짜를 넣지 않는다
- **발행 후 변경 금지**

## 10. 최종 기준

이 문서는 유일한 작업 기준이다. 이후 결과물에서 지침 누락이나 임의 변경이 발생하면 위반으로 본다.

네이버 세트와 Astro 세트는 **사실은 동일하되 문장 구조와 표현을 다르게** 구성한다. 네이버 세트의 문장을 그대로 재사용하지 않는다. 표현만 다르게 하되 두 세트의 정보량은 동일하게 유지한다.
